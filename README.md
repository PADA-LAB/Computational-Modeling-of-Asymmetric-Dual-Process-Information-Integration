# Computational Modeling of Asymmetric Dual-Process Information Integration  
**Evidence from Review Helpfulness Prediction**

Multi-platform S1/S2 Modeling with Fusion Strategies

## Research Pipeline Overview

```text
Raw Reviews
├─ S1: Feature-based Models
│     (LightGBM, XGBoost, CatBoost)
│
├─ S2: Text Embedding-based Models
│     (T5 Encoder + MLP / LightGBM, XGBoost, CatBoost)
│
└─ Fusion Strategies
    ├─ Early Fusion
    ├─ Residual Fusion
    └─ Late Fusion
```

## Environment Setup

The experiments were conducted using **Python 3.10.13**.

You can install the dependencies either in your local Python environment
or inside a virtual environment.  For reproducibility and dependency isolation, **using a virtual environment is recommended**.

```bash
git clone https://github.com/PADA-LAB/Computational-Modeling-of-Asymmetric-Dual-Process-Information-Integration.git
cd Computational-Modeling-of-Asymmetric-Dual-Process-Information-Integration

# (optional) create and activate virtual environment
python -m venv .venv
source .venv/bin/activate   # Linux / macOS
# .venv\Scripts\activate    # Windows

pip install -r requirements.txt
```
## Running Experiments

### Full Experiment (All Platforms & All Stages)
```bash
python -m src.main --config configs/runner.yaml
# or
make all
```

### Run a specific platform (all stages)
```bash
python -m src.main --platforms Amazon
python -m src.main --platforms Hotel
#or
make amazon
make hotel
```

### Run a specific stage (all platforms)
```bash
python -m src.main --stages s1
python -m src.main --stages s2
python -m src.main --stages late-fusion
#or
make s1
make s2
make late-fusion
```

### Platform + Stage
```bash
python -m src.main --platforms Amazon --stages s2
```

#### Available platforms & stages
```text
platforms | Amazon, Hotel, Coursera, Audible
stages | s1, s2, early-fusion, residual, late-fusion
```
Some stages require artifacts from earlier stages:
- s1: creates train/test indices and S1 predictions
- s2: requires `train_idx.npy` and `test_idx.npy` (created by s1)
- early-fusion: requires S2 embedding cache (`X_all.npy`) generated by s2
- residual: requires both S1 predictions and S2 embedding cache
- late-fusion: requires S1 prediction CSVs and S2 prediction dict pickle

## Configuration

All experimental settings are defined in `configs/runner.yaml`.

Key configuration sections include:

- `experiment`: random seeds, Optuna trials, and model lists for S1/S2
- `s1_features`: platform-specific feature columns used for S1 models
- `embedding`: T5 encoder embedding configuration
- `finetune`: optional LoRA-based fine-tuning of the T5 encoder
- `late_fusion`: fusion weight search step size
- `paths`: dataset locations and output directories for each platform

Modifying these settings will directly affect the experimental results.


## Output Artifacts

All experimental results are stored under:
```
outputs/<PLATFORM>/seed_<SEED>/
```
This directory contains prediction-level outputs and evaluation metrics
required to reproduce all reported results and subsequent fusion stages.

Fusion results are organized by fusion strategy (Early, Residual, Late)
under each platform and seed.

## Optional: LoRA Fine-tuned T5-base

Enable in config:

```yaml
finetune:
  enabled: true
```


LoRA adapters are stored per platform and reused automatically.
